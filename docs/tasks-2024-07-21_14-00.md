# Task List: Remove Enrollment Activity State and Rely on Pass Activity

1. [x] **Review and Document Current Model**
   - Identify all usages of `IsActive` or similar activity state on the `Enrollment` entity/model in the codebase.
   - Document all business logic, queries, and services that reference or set `Enrollment.IsActive`.

2. [x] **Update Domain Model**
   - Remove the `IsActive` property from the `Enrollment` class in the domain model.
   - Update the Entity Framework model and configuration to remove the `IsActive` column from the database schema.

3. [x] **Refactor Business Logic**
   - Refactor all business logic and service methods to determine enrollment activity by checking the associated Pass’s activity and validity period (`Pass.IsActive`, `Pass.StartDate`, `Pass.EndDate`).
   - Ensure all logic that previously relied on `Enrollment.IsActive` now uses Pass state.

4. [x] **Update Repository and Query Logic**
   - Refactor all repository methods and LINQ queries that filter or return enrollments based on `Enrollment.IsActive` to instead join with Pass and filter by Pass activity.
   - Update any related stored procedures or raw SQL queries if present.

5. [x] **Update API and Controller Logic**
   - Refactor API endpoints and controller actions to use the new logic for determining active enrollments.
   - Ensure all DTOs and API contracts reflect the updated model.

6. [x] **Update Frontend and Consumer Logic**
   - Update Blazor components and any other consumers to use the new definition of active enrollment (via Pass) when displaying eligible students or marking attendance.
   - Ensure UI logic and state management are consistent with the backend changes.

7. [x] **Database Migration and Data Cleanup**
   - Create and apply a database migration to drop the `IsActive` column from the `Enrollments` table.
   - Clean up any orphaned or inconsistent data related to enrollment activity.

8. [x] **Testing and Validation**
   - Update and run all relevant unit, integration, and UI tests to ensure the new logic is correct and no regressions are introduced.
   - Add or update tests to cover edge cases related to pass expiry, suspension, and class cancellation.

9. [x] **Documentation Update**
   - Update all relevant documentation, developer notes, and API contracts to reflect the new approach to enrollment activity.
   - Document the rationale for the change and its impact on business logic and data integrity.

10. [x] **Critical Review and User Approval**
    - Review the plan and completed tasks against the .clinerules (KISS, YAGNI, SRP, DRY).
    - Request user review and approval before proceeding with code implementation.
